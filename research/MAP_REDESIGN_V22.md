# 지도 재설계 v22

2026-09-29. 사용자의 ‘전문가를 불러 다시 설계’ 요청에 따라 **지도 UX 전문 리뷰 역할의 AI 에이전트**와 코드·설계를 검토했다. 실제 인간 전문가를 섭외하거나 현장 이용자 조사를 진행한 것은 아니다.

## 문제와 변경

| 이전 문제 | v22 대응 |
| --- | --- |

| 기준점이 적어 어느 동네인지 파악하기 어려움 | 타일 데이터에 있는 주요 궁궐·공원·역과 일부 동네 이름을 복구 |
| 건물 표시가 늦어 거리 구조가 텅 빈 선망으로 보임 | 줌 14부터 옅은 건물 면을 점진적으로 표시 |

## 유지한 조건

- 흰 바탕, 낮은 채도의 중성색, 선택에만 노란색. 녹색·붉은색·그라데이션 없음.
- 실제 사진의 비율·워터마크·출처 보존. 사진을 잘라내는 제안은 적용하지 않음.
- 수성동 계곡·이상의 집은 대략적 좌표라는 점선 표시와 설명 유지.
- 두 장소를 잇는 임의 경로선·도보 시간·현재 위치를 만들지 않음.
- 지도 실패 시 이름·상세 주소를 이용할 수 있는 목록과 재시도 유지.
- 키보드 버튼, 선택 상태, 라이브 안내와 기존 비교/상세 URL 흐름 유지.

## 자료와 구현

- 기존 OpenFreeMap Positron의 벡터 소스·글리프 설정과 출처를 재사용했다.
- 기준점은 타일 POI/park의 실제 이름으로 필터링한다. 경복궁·창덕궁·광화문·사직공원·사직단·일부 주요 문화시설 등 작은 목록이며 좌표를 수작업으로 만들지 않는다.
- [OpenMapTiles POI 필드](https://github.com/openmaptiles/openmaptiles/blob/master/layers/poi/poi.yaml), [park 필드](https://github.com/openmaptiles/openmaptiles/blob/master/layers/park/park.yaml)를 참고했다. 해당 지명의 실제 표시 여부는 공급 데이터와 확대 수준·충돌 배치에 달려 있다.
- 스타일 생성: `python scripts/build_map_style.py`. 장소/선택 상태는 `js/map.js`, 지역 URL 동기화는 `js/app.js`, 화면 구성은 `css/map-view.css`.

## 관찰 범위

브라우저 미리보기에서 안국 지도, 전체 두 지역 지도, 서촌 진입, 수성동 선택, 두 장소 비교를 직접 살펴봤다. 390×844에서 선택·비교 화면을, 320×568에서 두 핀 이름의 경계와 하단 배치를 확인했다. 320×568 비교 상태에서 지도 160px, 도크 247px, 문서 높이 568px였으며 두 이름이 지도 안에 배치됐다.

667×375 가로 화면의 비교쌍 초기 목록도 살펴봤다. 지도 내부 높이 178px, 도크 144px를 유지하며 문서 높이 485px로 페이지 스크롤을 허용한다. 이름 목록이 0px 수준으로 접히는 현상을 피하도록 구성했다.

독립 에이전트가 정적으로 재검토해 로딩 중 선택과 낮은 화면 문제를 지적했고 이를 수정했다. 자동 테스트를 추가하거나 실행하지 않았다. 실제 현장·보조기기·느린 네트워크 장애 주입·모든 줌 수준의 라벨 배치는 별도 검증이 필요하다.
