# 안국·서촌 앱 합성 사용 평가

작성: 2026-09-29. 대상: localhost:8765, 정적 리소스 v17.

**실제 참가자 0명. 합성 사례 100개.** 4개 비교쌍에 25가지 조건을 적용한 규칙 기반 가설 평가다. 대표 흐름만 실제 브라우저에서 조작했고, 100명의 독립적인 앱 사용이나 실제 현장 이동을 실행하지 않았다. 발언은 모두 창작된 합성 발언이다. 만족도·성공률·이탈률·인구 구성비는 산출하지 않는다.

## 요약

목적별 사진 비교, 양쪽 공통 상세, 출처 제공은 유지할 가치가 있다. 다음 수정은 새 색상이나 기능 확대보다 **방문 결정에 필요한 정보를 앞에 두고, 현재 조작의 가림과 잘못된 기대를 줄이는 작업**이 우선이다.

## 3. 수정 우선순위

### 1순위 — 지금 있는 화면에서 생기는 마찰

1. **고정 지도 버튼의 가림 제거.** 버튼이 차지하는 영역과 콘텐츠 영역을 분리하거나 툴바에 배치한다. 마지막 카드에 여백만 더하는 방법은 중간 행의 가림을 해결하지 못한다. 수정 후 첫 카드 비용과 마지막 카드 버튼을 각각 확인한다.
2. **길찾기 명칭과 실제 연결을 맞추기.** 현재 검색 링크를 유지한다면 ‘네이버 지도에서 보기’로 변경한다. 실제 경로 연결을 제공할 때만 ‘길찾기’라고 쓴다.
3. **핀 키보드 조작 확인·보완.** UI05를 실제 브라우저 키보드 입력으로 재현해 Enter/Space와 클릭의 결과가 같도록 한다. 실제 스크린리더 검증 완료라고 표현하지 않는다.

### 2순위 — 갈 곳을 결정하는 정보

4. **운영 요약을 상세 상단으로 올리기.** 사진과 긴 소개보다 장소명 아래에 짧은 기본 운영시간·정기 휴무·확인 링크를 배치한다. 영업 중/여유 좌석/대기 없음은 근거 없이 추가하지 않는다. 긴 예외는 펼쳐보기로 이동한다.
5. **입구와 비용의 빈칸 채우기.** 수성동·이상의 집 입구 좌표, 장소별 비용 조건, 문턱·계단 정보를 우선 확인한다. 확인 전에는 미확인을 유지한다. 정보 부족은 색상 변경으로 해결되지 않는다.
6. **상대 장소 전환을 상세 위쪽으로 올리기.** 기존 링크를 재배치해 두 상세를 번갈아 살펴보게 한다. 추가 탭이나 새 화면을 만들 필요는 없다.

### 3순위 — 읽는 양과 이동량 줄이기

7. **중복 설명을 줄이고 중요한 글자를 키우기.** 상황 제목·비교 이유·각 장소의 방문 목적이 같은 말을 반복하는지 편집한다. 1A/1B는 지도 연계에 필요한 위치에서 사용하고, 모든 라벨을 설명 문장처럼 강조하지 않는다. 큰 빈 여백보다 읽어야 할 핵심을 줄이는 편집을 먼저 한다.
8. **네 가지 상황을 빨리 찾게 하기.** 새 필터 패널을 만들기 전에 짧은 상황별 이동 링크를 검토한다. 실제로 네 번째 비교를 못 찾는지 사용자 관찰로 확인한다.

### 현재 보류할 추가 기능

계정, 즐겨찾기 시스템, 리뷰 작성, AI 추천, 다수의 필터, 자동 날씨 판단, 실시간 혼잡도. 이번 가정만으로 사용 수요나 데이터 신뢰성을 입증하지 못했다. 공유 필요는 이미 있는 상세 URL부터 활용한다.

## 4. 유지할 요소

- 실제 장소 사진과 공통 ‘공간·비용’ 비교.
- 양쪽 장소에서 같은 상세를 여는 구조.
- 흰 바탕·차콜 본문·선택 및 주요 행동에 쓰는 노란색.
- 공식 출처와 자료 확인일, 미확인 정보의 명시.
- 두 장소만 지도에서 비교하고 해당 카드로 돌아가는 흐름.

## 5. 실행하지 않은 것

현장 보행, 실제 입구 도착, 영업 여부 재조사, 외부 지도 앱 실행·복귀, 실제 외국어 사용자, 시각·운동 접근성 사용자 관찰, 느린 네트워크/오프라인 주입, iOS/Android 실기기 평가, 만족도 조사. 100개 합성 사례는 이 빈칸을 실제 검증으로 바꾸지 않는다.

합성 사례 수를 세어 ‘100명 중 몇 명이 불편했다’고 보고하면 안 된다. 같은 25개 조건을 네 쌍에 반복 적용했기 때문에 반복 횟수는 평가 설계로 정해진다. 사례는 누락된 상황을 찾는 점검 목록으로 사용한다.
